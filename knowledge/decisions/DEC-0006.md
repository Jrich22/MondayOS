TASK-0033 established the future-compatibility contract for the Cue data model: CueEvent is the container every operations surface hangs off. Guest management, roll call, seating, agenda, vendors, documents, and analytics are each their own collection keyed by CueEvent.id — never nested inline on the event. This makes adding them additive with no redesign. The create-event flow captures the fields those surfaces read: stable id, classification (typed enum + custom free-text), capacity policy (maxAttendees|null + rsvpEnabled + waitlistEnabled), timezone-aware start/end, and branding (theme + banner/logo placeholders). MVP persistence is localStorage behind a single store seam (src/lib/store.ts): seed events are immutable, user-created events overlay on top, and useEvents() is the reactive read path. Swapping to a real API changes only store.ts. Component: cue-app.
