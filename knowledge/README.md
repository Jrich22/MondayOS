# knowledge

Structured engineering knowledge base for MondayOS.

## Responsibility

The knowledge module accumulates everything MondayOS learns over time: bugs resolved, decisions made, patterns discovered, and operational procedures documented. AI agents query this before starting any task. Humans browse it to understand why the system is the way it is.

The primary principle: **never solve the same problem twice.** Every resolved bug and every meaningful decision creates a knowledge entry.

## What This Module Does NOT Own

- Search and ranking of entries — that is `search.SearchEngine`.
- Event emission — the store publishes to the `EventBus` but does not own it.
- Task records — those are in `tasks/`.
- Human-facing documentation — that is in `docs/`.

## Public Interface

| Symbol | Description |
|---|---|
| `KnowledgeStore` | The only path to read/write knowledge entries |
| `KnowledgeEntry` | Data model for all entry types |
| `EntryType` | `BUG`, `DECISION`, `PATTERN`, `RUNBOOK` |
| `EntryStatus` | `ACTIVE`, `DEPRECATED`, `SUPERSEDED` |
| `KnowledgeLoader` | Discovers and loads entry `.md` files from disk |
| `KnowledgeParser` | Parses Markdown + YAML frontmatter into `KnowledgeEntry` |
| `KnowledgeIndex` | Fast in-memory index for lookup by ID, type, tag, component |

## Internal File Layout

```
knowledge/
├── bugs/       BUG-NNNN.md
├── decisions/  DEC-NNNN.md
├── patterns/   PAT-NNNN.md
├── runbooks/   RUN-NNNN.md
└── index.md    ← auto-generated by KnowledgeIndex.write_markdown_index()
```

## Dependencies

- `core.types` — `EntityId`, `Timestamp`
- `search` — `SearchEngine` (for full-text query delegation)
- `events` — `EventBus` (to publish KNOWLEDGE_ENTRY_CREATED events)

## Configuration

- `KNOWLEDGE_DIR` — path to the knowledge/ directory (default: `./knowledge`)
