# Cue App: Organization & Relationship Intelligence Foundation

## Architecture Design Document v1.0

---

## Executive Summary

This document defines the long-term domain model and architecture for Cue App's organizational memory system. The design prioritizes relationship intelligence, AI-augmented recommendations, and cross-event analytics while remaining implementable incrementally without requiring a graph database or specialized infrastructure at launch.

The core insight: **every entity in the Cue system is a node, and every interaction between entities is an edge with temporal weight.** This document makes that model concrete and actionable.

---

## 1. Design Principles

### 1.1 Foundational Constraints

| Principle | Rationale |
|-----------|-----------|
| **Relatability over normalization** | Every entity must be linkable to every other entity via a defined relationship type |
| **Temporal awareness** | All relationships carry timestamps and confidence decay |
| **AI-first schema** | Every entity carries an `ai_context` block for embedding storage and inference hints |
| **Tenant isolation** | All data scoped to `organization_id` — no cross-tenant leakage |
| **Incremental complexity** | Start with PostgreSQL + JSONB; migrate to graph layer when query patterns demand it |

### 1.2 What This Model Must Support

- Attendee history across multiple events within and across organizations
- Vendor performance tracking and relationship scoring
- Networking intelligence ("who has met whom, when, and in what context")
- AI recommendations ("based on past events, suggest vendors/speakers/venues")
- Cross-event analytics (attendance trends, relationship evolution, topic clustering)
- Communication history linked to entities (not just events)

## 2. Core Domain Entities

### 2.1 Entity Hierarchy Overview

```
Organization (tenant root)
├── Workspace (project/team container)
│   ├── Event (primary activity)
│   │   ├── EventSession (sub-unit of event)
│   │   ├── EventAttendee (Person × Event junction)
│   │   ├── EventVendor (Vendor × Event junction)
│   │   └── EventDocument (Document × Event junction)
├── Person (persistent identity)
│   ├── PersonCompanyAffiliation (Person × Company × time)
│   └── PersonEventHistory (derived / materialized)
├── Company (persistent entity)
│   └── CompanyVendorProfile (when Company acts as vendor)
├── Venue (physical/virtual location)
├── Vendor (service provider — may be backed by Company)

```

## 3. Entity Specifications

### 3.1 Organization

The tenant root. All other entities belong to an Organization.

```typescript
interface Organization {
  id: UUID;
  name: string;
  slug: string;                          // URL-safe identifier
  plan_tier: 'starter' | 'growth' | 'enterprise';
  
  settings: {
    ai_features_enabled: boolean;
    relationship_tracking_depth: number;  // how many hops to traverse for insights
    data_retention_days: number;
    default_timezone: string;
  };
  
  ai_context: AIContextBlock;            // org-level intelligence (industry, size, patterns)
  
  created_at: Timestamp;
  updated_at: Timestamp;
}
```

**Key relationships:**
- `has_many` Workspaces
- `has_many` People (directory)
- `has_many` Companies (CRM)
- `has_many` Vendors (supplier directory)

---

### 3.2 Workspace

A logical container for a team, department, or project. Enables scoping without full tenant separation.

```typescript
interface Workspace {
  id: UUID;
  organization_id: UUID;                 // FK → Organization
  
  name: string;
  description: string;
  workspace_type: WorkspaceType;
  
  members: WorkspaceMember[];           // People with roles in this workspace
  
  settings: {
    visibility: 'public' | 'private' | 'restricted';
    inherit_org_vendors: boolean;       // use org vendor directory vs. workspace-specific
    ai_memory_scope: 'workspace' | 'organization';  // boundary for AI context
  };
  
  ai_context: AIContextBlock;
  
  created_at: Timestamp;
  updated_at: Timestamp;
}

type WorkspaceType = 
  | 'events_team'
  | 'executive'
  | 'marketing'
  | 'operations'
  | 'client_account';

interface WorkspaceMember {
  person_id: UUID;
  role: 'owner' | 'admin' | 'editor' | 'viewer';
  joined_at: Timestamp;
}
```
