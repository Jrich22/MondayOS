# Cue App: Organization & Relationship Intelligence Foundation

## Domain Model & Architecture Specification

---

## Executive Summary

This document defines the canonical long-term data model for the Cue App's organizational memory system. It establishes how the ten core domain entities relate to one another, how AI context is captured and surfaced, and how the system supports relationship intelligence, cross-event analytics, and networking insights — without requiring a graph database or production backend at this stage.

The model is intentionally storage-agnostic: it can be realized in PostgreSQL (with JSONB for flexible attributes), migrated to a graph database later, or served via a document store. The architecture prioritizes **forward compatibility** and **relationship traversal** over premature optimization.

---

## 1. Core Domain Entities

### 1.1 Entity Inventory

| Entity | Purpose | Primary Key Pattern |
|---|---|---|
| `Organization` | Root tenant; owns all data | `org_{ulid}` |
| `Workspace` | Sub-division of an org (team, department, business unit) | `ws_{ulid}` |
| `Person` | Human actor — attendee, speaker, staff, contact | `per_{ulid}` |
| `Company` | External organization a Person is affiliated with | `co_{ulid}` |
| `Event` | Time-bounded gathering (conference, meeting, workshop) | `evt_{ulid}` |
| `Venue` | Physical or virtual location | `ven_{ulid}` |
| `Vendor` | External service provider engaged for an Event | `vnd_{ulid}` |
| `Document` | Artifact produced or consumed in context | `doc_{ulid}` |
| `Communication` | Message, email, note, or interaction record | `com_{ulid}` |
| `AIContext` | Structured AI memory unit attached to any entity | `aic_{ulid}` |

> **ULID** is preferred over UUID for sortability and debuggability. All IDs are globally unique across entity types by prefix convention.

### 2.3 Person

```typescript
interface Person {
  id: string;                          // "per_{ulid}"
  organizationId: string;              // FK → Organization (owning org)
  
  // Identity
  firstName: string;
  lastName: string;
  email: string;                       // Canonical contact email
  emailAliases: string[];              // For deduplication across imports
  phone: string | null;
  avatarUrl: string | null;
  
  // Professional context
  currentCompanyId: string | null;     // FK → Company
  currentTitle: string | null;
  currentDepartment: string | null;
  linkedInUrl: string | null;
  twitterHandle: string | null;
  
  // System role
  role: PersonRole;
  workspaceMemberships: WorkspaceMembership[];

  firstSeenAt: DateTime;
```
