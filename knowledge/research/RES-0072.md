# Cue App: Organization & Relationship Intelligence Foundation

## Architecture & Domain Model

---

## Executive Summary

This document defines the long-term data model and relational architecture for the Cue App's organizational memory system. The model is designed to support relationship intelligence, AI-driven recommendations, attendee history tracking, networking insights, and cross-event analytics — without prescribing a specific backend implementation.

The architecture follows a **Domain-Driven Design (DDD)** approach with clear aggregate boundaries, enabling future migration to graph databases, event-sourced systems, or distributed architectures without model redesign.

---

## 1. Core Design Principles

1. **Entities are first-class** — Organizations, People, and Events are never ephemeral; they accumulate history
2. **Relationships carry metadata** — Every edge in the model stores temporal, contextual, and confidence data
3. **AI context is a first-class citizen** — Every entity can carry AI-generated signals, embeddings, and recommendation surfaces
4. **Temporal integrity** — All relationships have `effective_from` / `effective_to` to support point-in-time queries
5. **Multi-tenancy by design** — Workspace isolation is enforced at the model level, not the application layer
6. **Event sourcing-ready** — State changes are additive; history is never destroyed

## 3. Entity Definitions & Schemas

### 3.1 Organization

The root aggregate. Every other entity lives within or relates to an Organization.

```typescript
interface Organization {
  id: UUID;                          // Immutable primary key
  slug: string;                      // URL-safe unique identifier
  name: string;
  type: OrganizationType;            // 'enterprise' | 'agency' | 'nonprofit' | 'individual'
  tier: SubscriptionTier;            // Controls feature access
  
  // Identity & branding
  logoUrl?: string;
  primaryDomain?: string;            // Used for email-based company matching
  
  // Temporal
  createdAt: Timestamp;
  updatedAt: Timestamp;
  deletedAt?: Timestamp;             // Soft delete only — history preserved
  
  // AI signals
  aiProfile: OrganizationAIProfile;
  
  // Relationships (foreign keys — not embedded)
  workspaceIds: UUID[];
  primaryContactId?: UUID;           // Person reference
}

type OrganizationType = 'enterprise' | 'agency' | 'nonprofit' | 'individual' | 'government';
type SubscriptionTier = 'free' | 'pro' | 'business' | 'enterprise';

interface OrganizationAIProfile {
  industryTags: string[];            // AI-inferred from event history
  eventStyleSignature: string[];     // e.g., ['high-production', 'intimate', 'conference']
  preferredVendorCategories: string[];
  networkDensityScore: number;       // 0-1: how interconnected their People network is
  lastProfiledAt: Timestamp;
}
```

### 3.2 Workspace

Workspaces enable multi-team isolation within a single Organization. Each Workspace is a scoped operational context.

```typescript
interface Workspace {
  id: UUID;
  organizationId: UUID;              // Parent organization
  name: string;
  slug: string;
  
  // Access control
  visibility: WorkspaceVisibility;   // 'private' | 'org-wide' | 'public'
  memberIds: UUID[];                 // Person references
  adminIds: UUID[];
  
  // Configuration
  settings: WorkspaceSettings;
  defaultCurrencyCode: string;       // ISO 4217
  timezone: string;                  // IANA timezone
  
  // Temporal
  createdAt: Timestamp;
  archivedAt?: Timestamp;
  
  // Cross-workspace intelligence
  sharedVenuePoolEnabled: boolean;   // Can see org-level venue history
  sharedVendorPoolEnabled: boolean;
  crossEventAnalyticsEnabled: boolean;
}

type WorkspaceVisibility = 'private' | 'org-wide' | 'public';

interface WorkspaceSettings {
  defaultEventTemplate?: UUID;
  aiRecommendationsEnabled: boolean;
  autoRelationshipDetection: boolean; // AI-suggested links between people/companies
  communicationIngestionEnabled: boolean;
  budgetAlertThreshold?: number;
}
```
