# Cue App: Organization & Relationship Intelligence Foundation

## Architecture & Domain Model

---

## Executive Summary

This document defines the long-term data model and relationship architecture for the Cue App's organizational memory system. The design prioritizes relationship intelligence, AI-readiness, cross-event analytics, and extensibility — without prematurely committing to a graph database or production backend infrastructure.

The architecture uses a **hybrid relational-graph conceptual model**: entities are defined relationally (suitable for PostgreSQL, SQLite, or similar), with explicit relationship tables that allow graph traversal patterns when needed. AI context is a first-class citizen throughout.

---

## 1. Core Design Principles

### 1.1 Principles

| # | Principle | Rationale |
|---|-----------|-----------|
| 1 | **Identity over Duplication** | A person or company exists once; appearances across events are *attendances*, not copies |
| 2 | **Relationships are Data** | Connections between entities are explicit, typed, and timestamped — not inferred at query time |
| 3 | **AI Context is First-Class** | Every major entity carries an `ai_context` payload for embedding storage, summaries, and recommendation signals |
| 4 | **Event-Scoped vs. Global** | Distinguish between global records (a Person) and event-scoped records (an Attendance) |
| 5 | **Audit Everything** | All mutations carry `created_at`, `updated_at`, `created_by`, with soft deletes |
| 6 | **Extensible by Design** | `metadata JSONB` fields allow domain extension without schema migrations |

## 3. Entity Definitions

### 3.1 Organization Layer

```sql
-- ============================================================
-- ORGANIZATIONS
-- Top-level tenant. Could be an event company, a corporation,
-- a professional association, etc.
-- ============================================================

CREATE TABLE organizations (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            TEXT NOT NULL,
    slug            TEXT UNIQUE NOT NULL,           -- URL-safe identifier
    domain          TEXT,                           -- email domain for auto-matching
    logo_url        TEXT,
    industry        TEXT,
    size_range      TEXT,                           -- 'startup','smb','enterprise'
    website         TEXT,
    description     TEXT,
    ai_context      JSONB DEFAULT '{}',             -- embeddings, summaries, signals
    metadata        JSONB DEFAULT '{}',             -- extensible
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ                     -- soft delete
);

-- ============================================================
-- WORKSPACES
-- A workspace is an operational unit within an organization.
-- One org may have "Conferences Division" and "Training Division"
-- as separate workspaces, each managing their own events.
-- ============================================================

CREATE TABLE workspaces (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id),
    name            TEXT NOT NULL,
    slug            TEXT NOT NULL,
    description     TEXT,
    settings        JSONB DEFAULT '{}',             -- workspace-level config
    ai_context      JSONB DEFAULT '{}',
    metadata        JSONB DEFAULT '{}',
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ,
    UNIQUE(organization_id, slug)
);

-- ============================================================
-- WORKSPACE MEMBERSHIP
-- Who belongs to a workspace and in what role.
-- ============================================================

CREATE TABLE workspace_memberships (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id    UUID NOT NULL REFERENCES workspaces(id),
    person_id       UUID NOT NULL REFERENCES people(id),
    role            TEXT NOT NULL DEFAULT 'member', -- 'owner','admin','member','viewer'
    permissions     JSONB DEFAULT '{}',             -- fine-grained ACL if needed
    joined_at       TIMESTAMPTZ DEFAULT NOW(),
    left_at         TIMESTAMPTZ,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.2 People Layer

```sql
-- ============================================================
-- PEOPLE
-- A person is a global identity. The same human appears
-- once here regardless of how many events they attend.
-- ============================================================

CREATE TABLE people (

    -- Identity
    first_name      TEXT NOT NULL,
    last_name       TEXT NOT NULL,
    preferred_name  TEXT,
    pronouns        TEXT,
    -- Contact
    primary_email   TEXT UNIQUE,
    emails          JSONB DEFAULT '[]',             -- [{email, type, verified}]
    phone_numbers   JSONB DEFAULT '[]',             -- [{number, type}]
    -- Professional
    current_title   TEXT,
    bio             TEXT,
    linkedin_url    TEXT,
    twitter_handle  TEXT,
    website         TEXT,
    -- Media
    avatar_url      TEXT,
    -- Intelligence
    ai_context      JSONB DEFAULT '{}',             -- {embedding, summary, topics[], signals}
    relationship_score DECIMAL(5,2),               -- computed: overall network value
    engagement_tier TEXT,                           -- 'vip','regular','new','lapsed'

    deleted_at      TIMESTAMPTZ
