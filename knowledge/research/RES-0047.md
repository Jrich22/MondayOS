### Architecture Decisions

Before writing code, I'll establish the key decisions:

1. **Data shape**: Events have `id`, `title`, `date`, `venue`, `status`, `ticketsSold`, `capacity`, `revenue`
2. **Status states**: `draft` | `on_sale` | `sold_out` | `cancelled` | `completed`
3. **No auth, no payments, no integrations** — MVP scope strictly enforced
4. **State management**: Local React state + custom hook (no Redux overhead for MVP)
5. **Styling**: CSS Modules (avoids global collisions, no extra deps)

```typescript
export type EventStatus =
  | 'draft'
  | 'on_sale'
  | 'sold_out'
  | 'cancelled'
  | 'completed';

export interface CueEvent {
  id: string;
  title: string;
  date: string;          // ISO 8601
  venue: string;
  status: EventStatus;
  ticketsSold: number;
  capacity: number;
  revenue: number;       // cents, to avoid float arithmetic
  createdAt: string;     // ISO 8601
  updatedAt: string;     // ISO 8601
}

export type EventSortKey = 'date' | 'title' | 'status' | 'ticketsSold';
export type SortDirection = 'asc' | 'desc';

export interface EventFilters {
  status: EventStatus | 'all';
  search: string;
}
```
