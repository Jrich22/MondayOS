# Cue App: Multi-Organization Architecture Design

## Executive Summary

This document defines the complete multi-organization architecture for the Cue App, enabling support for Venture Capital, Private Equity, Conferences, Corporate Events, Executive Offsites, Customer Advisory Boards, University Alumni, Nonprofits, and Associations. This is a **design-only deliverable** — no production backend or auth is implemented here.

---

## 1. Organization Model

### 1.1 Core Organization Entity

```typescript
// types/organization.ts

export type OrganizationType =
  | 'venture_capital'
  | 'private_equity'
  | 'conference'
  | 'corporate_event'
  | 'executive_offsite'
  | 'customer_advisory_board'
  | 'university_alumni'
  | 'nonprofit'
  | 'association';

export type OrganizationStatus = 'trial' | 'active' | 'suspended' | 'churned';
export type BillingTier = 'free' | 'starter' | 'growth' | 'enterprise';

export interface Organization {
  // Identity
  id: string;                          // UUID v4
  slug: string;                        // URL-safe unique identifier (e.g. "sequoia-capital")
  name: string;
  type: OrganizationType;
  status: OrganizationStatus;

  // Branding
  logoUrl?: string;
  brandColor?: string;                 // Hex color for white-label theming
  domain?: string;                     // e.g. "sequoia.com" for SSO domain matching

  // Billing & Tier
  billingTier: BillingTier;
  billingEmail: string;
  maxWorkspaces: number;               // Derived from billingTier; -1 = unlimited
  maxMembersPerWorkspace: number;      // Derived from billingTier; -1 = unlimited

  // Industry Profile Reference
  industryProfileId: string;           // FK → IndustryProfile.id

  // Feature Flags (org-level overrides)
  featureFlags: OrganizationFeatureFlags;

  // Custom Fields (org-level)
  customFields: CustomFieldValue[];

  // Metadata
  ownerId: string;                     // FK → User.id
  createdAt: string;                   // ISO 8601
  updatedAt: string;
  deletedAt?: string;                  // Soft delete
}
```

## 2. Workspace Model

Workspaces are sub-units within an organization. A VC firm might have one workspace per fund; a conference company might have one workspace per event.

### 2.1 Core Workspace Entity

```typescript
// types/workspace.ts

export type WorkspaceType =
  | 'fund'                   // VC / PE
  | 'event'                  // Conference / Corporate Event / Offsite
  | 'cohort'                 // CAB / Alumni / Nonprofit programs
  | 'chapter'                // Association / Alumni regional chapter
  | 'general';               // Default, uncategorized

export interface Workspace {
  // Identity
  id: string;
  organizationId: string;              // FK → Organization.id
  name: string;
  slug: string;                        // Unique within org
  type: WorkspaceType;
  description?: string;

  // Dates (relevant for event-type workspaces)
  startsAt?: string;                   // ISO 8601 — event start
  endsAt?: string;                     // ISO 8601 — event end

  // Industry Profile Reference (can override org-level profile)
  industryProfileId?: string;          // If null, inherits from Organization

  // Configuration
  featureFlags: WorkspaceFeatureFlags; // Inherits from org; can further restrict
  customFields: CustomFieldValue[];

  // Access
  visibility: 'private' | 'org_wide' | 'public';

  // Metadata
  createdBy: string;
  createdAt: string;
  updatedAt: string;
  archivedAt?: string;
}
```

### 2.2 Workspace Member

```typescript
// types/workspace-member.ts

export type WorkspaceRole =
  | 'workspace_owner'
  | 'editor'
  | 'contributor'
  | 'viewer';

export interface WorkspaceMember {
  id: string;
  workspaceId: string;
  userId: string;
  organizationId: string;              // Denormalized for query efficiency
  role: WorkspaceRole;
  joinedAt: string;
  // A user must be an OrganizationMember to be a WorkspaceMember
}
```

### 2.3 Workspace Inheritance Rules

```
Organization
  ├── featureFlags          ← authoritative ceiling
  ├── industryProfileId     ← default profile
  └── Workspace[]
        ├── featureFlags    ← can only DISABLE features org has enabled
        └── industryProfileId ← can OVERRIDE org profile (subset or different vertical)
```

## 3. Industry Profile System

Industry profiles bundle the default configuration, terminology, and feature set appropriate for each organization type. They are the primary lever for customization without code changes.

### 3.1 IndustryProfile Entity

```typescript
// types/industry-profile.ts

export interface IndustryProfile {
  id: string;
  organizationType: OrganizationType;  // One canonical profile per type (extensible)
  version: string;                     // Semver — allows migrations
  displayName: string;                 // e.g. "Venture Capital"
  description: string;

  // Terminology overrides — replaces generic labels in UI
  terminology: TerminologyMap;

  // Default custom field schemas for this profile
  defaultCustomFieldSchemas: CustomFieldSchema[];

  // Default feature flag configuration for this profile
  defaultFeatureFlags: FeatureFlagConfig;

  // Navigation items to show/hide by default
  defaultNavigation: NavigationConfig;

  // Default workspace types available
  allowedWorkspaceTypes: WorkspaceType[];

  // Metadata
  isSystem: boolean;                   // System profiles are read-only
  createdAt: string;
  updatedAt: string;
}
```

### 3.2 Terminology Map

Different org types use radically different language for the same concepts.

```typescript
// types/terminology.ts

export interface TerminologyMap {
  // Core entity labels (singular / plural)
  member:        { singular: string; plural: string };

  contact:       { singular: string; plural: string };
  note:          { singular: string; plural: string };
  tag:           { singular: string; plural: string };
  // Extensible — add keys as needed
  [key: string]: { singular: string; plural: string };
}
```
