# Cue App: Multi-Organization Architecture Design

## Executive Summary

This document defines the complete multi-organization architecture for the Cue App, enabling support for Venture Capital, Private Equity, Conferences, Corporate Events, Executive Offsites, Customer Advisory Boards, University Alumni, Nonprofits, and Associations. The design covers the organization model, workspace model, industry profile system, configurable fields, feature flags, permissions, and multi-tenant architecture path.

---

## 1. Core Architectural Principles

### 1.1 Design Philosophy

| Principle | Description |
|-----------|-------------|
| **Profile-Driven Configuration** | Each organization type is defined by an `IndustryProfile` that activates/deactivates capabilities without code changes |
| **Convention Over Configuration** | Sensible defaults ship with each profile; customization is additive, not required |
| **Tenant Isolation by Default** | Data is scoped to `organization_id` from day one; multi-tenant migration is evolutionary, not disruptive |
| **Feature Flags as First-Class Citizens** | All new capabilities are gated; profiles toggle flags, not code paths |
| **Backward Compatibility** | Existing single-org deployments continue working via a `DEFAULT` organization wrapper |

### 1.2 Layered Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    Application Layer                     │
│         (React UI, API Routes, Business Logic)          │
├─────────────────────────────────────────────────────────┤
│                  Configuration Layer                     │
│     IndustryProfile → FeatureFlags → FieldSchemas       │
├──────────────────────────┬──────────────────────────────┤
│    Organization Model    │      Workspace Model         │
│  (Identity, Billing,     │  (Scoped Collaboration       │
│   Global Settings)       │   Context)                  │
├──────────────────────────┴──────────────────────────────┤
│                    Data Layer                            │
│         (Postgres with org_id/workspace_id row-          │
│          level scoping; future RLS policies)            │
└─────────────────────────────────────────────────────────┘
```

## 2. Organization Model

### 2.1 Core Organization Entity

```typescript
// types/organization.ts

export type OrganizationType =
  | 'venture_capital'
  | 'private_equity'
  | 'conference'
  | 'corporate_event'
  | 'executive_offsite'
  | 'customer_advisory_board'
  | 'university_alumni'
  | 'nonprofit'
  | 'association'
  | 'general'; // fallback / future types

export type OrganizationTier =
  | 'starter'    // single workspace, limited seats
  | 'growth'     // multiple workspaces, standard features
  | 'enterprise' // unlimited workspaces, all features, SSO
  | 'internal';  // MondayOS own orgs, all flags unlocked

export interface Organization {
  // Identity
  id: string;                          // UUID v4
  slug: string;                        // URL-safe, unique: "sequoia-capital"
  displayName: string;                 // "Sequoia Capital"
  legalName?: string;                  // "Sequoia Capital Operations, LLC"

  // Classification
  type: OrganizationType;
  industryProfileId: string;           // FK → IndustryProfile
  tier: OrganizationTier;

  // Contact & Branding
  logoUrl?: string;
  primaryColor?: string;               // hex, used in white-label contexts
  websiteUrl?: string;
  domainWhitelist: string[];           // ["sequoiacap.com"] for auto-join

  // Configuration Overrides (override profile defaults)
  featureFlagOverrides: Partial<FeatureFlagSet>;
  customFieldSchemaIds: string[];      // additional org-specific field schemas

  // Tenant Isolation
  dataRegion: 'us-east-1' | 'eu-west-1' | 'ap-southeast-1';
  encryptionKeyId?: string;            // for enterprise KMS

  // Lifecycle
  status: 'active' | 'suspended' | 'archived' | 'pending_setup';
  createdAt: Date;
  updatedAt: Date;
  archivedAt?: Date;

  // Relationships
  workspaceIds: string[];              // FK[] → Workspace
  ownerUserId: string;                 // FK → User (org admin)
  billingAccountId?: string;           // FK → BillingAccount
}
```

```typescript
  workspace: string;     // VC: "Fund", Conference: "Event Edition"
  pipeline: string;      // PE: "Deal Flow", Nonprofit: "Campaign"
  tag: string;
```

### 2.3 Organization Membership

```typescript
// types/organization-membership.ts

export type OrgRole =
  | 'org_owner'      // full control, billing, delete org
  | 'org_admin'      // manage members, settings, workspaces
  | 'org_member'     // access to assigned workspaces
  | 'org_guest';     // limited, time-boxed access

export interface OrganizationMembership {
  id: string;
  organizationId: string;
  userId: string;

  role: OrgRole;
  workspaceIds: string[];              // which workspaces they can access

  // Invite tracking
  invitedByUserId?: string;
  invitedAt?: Date;
  acceptedAt?: Date;

  // Time-boxing for guests
  expiresAt?: Date;

  status: 'active' | 'pending' | 'suspended' | 'expired';
  createdAt: Date;
  updatedAt: Date;
}
```
