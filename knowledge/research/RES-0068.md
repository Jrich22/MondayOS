# Cue App: Multi-Organization Architecture Design

## Executive Summary

This document defines the multi-organization architecture for the Cue App, enabling support for diverse organization types—from Venture Capital firms to University Alumni networks—through a flexible, profile-driven system. The design prioritizes configurability over hardcoding, clean tenant isolation boundaries, and a migration path from single-tenant to multi-tenant without breaking existing functionality.

---

## 1. Organization Model

### 1.1 Core Organization Entity

```typescript
// types/organization.ts

export type OrganizationCategory =
  | 'venture_capital'
  | 'private_equity'
  | 'conference'
  | 'corporate_events'
  | 'executive_offsite'
  | 'customer_advisory_board'
  | 'university_alumni'

  | 'association'
  | 'custom';

export type OrganizationTier = 'free' | 'starter' | 'professional' | 'enterprise';

export type OrganizationStatus = 'active' | 'suspended' | 'onboarding' | 'churned';

export interface Organization {
  // Identity
  id: string;                          // UUID v4
  slug: string;                        // URL-safe unique identifier (e.g., "sequoia-capital")
  displayName: string;
  legalName?: string;
  logoUrl?: string;
  brandColor?: string;                 // Hex, for white-labeling

  // Classification
  category: OrganizationCategory;
  industryProfileId: string;           // FK → IndustryProfile
  tier: OrganizationTier;

  // State
  status: OrganizationStatus;
  createdAt: Date;
  updatedAt: Date;
  suspendedAt?: Date;
  suspendedReason?: string;

  // Configuration (references to child entities)
  workspaceIds: string[];              // FK → Workspace[]
  featureFlagSetId: string;            // FK → FeatureFlagSet
  permissionSchemeId: string;          // FK → PermissionScheme
  customFieldSchemaId: string;         // FK → CustomFieldSchema

  // Billing & Limits
  billing: OrganizationBilling;

  // Custom metadata (escape hatch for org-specific data)
  metadata: Record<string, unknown>;
}

export interface OrganizationBilling {
  tier: OrganizationTier;
  maxMembers: number;
  maxWorkspaces: number;
  maxEventsPerYear: number;
  stripeCustomerId?: string;
  currentPeriodEnd?: Date;
}
```

## 2. Workspace Model

Workspaces are sub-units within an organization. A VC firm might have workspaces per fund; a conference org might have one per annual event.

```typescript
// types/workspace.ts

export type WorkspaceVisibility = 'private' | 'org_internal' | 'public';

export interface Workspace {
  // Identity
  id: string;
  organizationId: string;             // Parent organization
  slug: string;                       // Scoped to org (e.g., "fund-iii")
  displayName: string;
  description?: string;
  iconEmoji?: string;
  coverImageUrl?: string;

  // Typing
  workspaceType: WorkspaceType;       // Aligned with parent org category
  visibility: WorkspaceVisibility;

  // Configuration
  featureFlagOverrides: Partial<FeatureFlagSet>; // Workspace-level overrides
  customFieldSchemaId: string;        // Can inherit or override org schema
  permissionOverrides?: Partial<PermissionScheme>;

  // Event/Session context
  timezone: string;                   // IANA timezone string
  defaultLocale: string;              // BCP 47

  // Lifecycle
  status: 'active' | 'archived' | 'template';
  archivedAt?: Date;
  createdAt: Date;
  updatedAt: Date;

  // Membership
  memberIds: string[];                // OrganizationMember IDs with access
  adminIds: string[];                 // OrganizationMember IDs with admin

  metadata: Record<string, unknown>;
}

export type WorkspaceType =
  | 'fund'                 // VC/PE: per-fund workspace
  | 'portfolio'            // VC/PE: portfolio company tracking
  | 'event_series'         // Conference: recurring annual event
  | 'single_event'         // Corporate/Offsite: one-off event
  | 'cohort'               // Alumni: graduating class
  | 'chapter'              // Association/Alumni: geographic chapter
  | 'program'              // Nonprofit: program or initiative
  | 'board'                // CAB: advisory board instance
  | 'general';             // Fallback
```

## 3. Industry Profile System

Industry profiles define the *personality* of an organization type—default terminology, UI labels, default feature flags, suggested field schemas, and role naming. They are templates, not constraints.

```typescript
// types/industryProfile.ts

export interface IndustryProfile {
  id: string;
  category: OrganizationCategory;
  version: string;                    // Semver for profile schema evolution

  // Display
  displayName: string;
  description: string;
  iconName: string;

  // Terminology overrides (replaces generic "Event", "Member", etc.)
  terminology: TerminologyMap;

  // Default feature flag set for this profile
  defaultFeatureFlags: FeatureFlagSet;

  // Suggested custom field schema
  suggestedFieldSchema: CustomFieldSchemaDefinition;

  // Default workspace types available
  availableWorkspaceTypes: WorkspaceType[];
  defaultWorkspaceType: WorkspaceType;

  // Default permission scheme
  defaultPermissionScheme: PermissionSchemeDefinition;

  // Onboarding flow config
  onboardingSteps: OnboardingStep[];
}

export interface TerminologyMap {
  organization: string;    // e.g., "Firm", "Fund", "Conference", "Chapter"
  workspace: string;       // e.g., "Fund", "Event", "Cohort", "Program"
  member: string;          // e.g., "Partner", "Attendee", "Alumni", "Member"
  event: string;           // e.g., "Session", "Cue", "Meeting", "Gathering"
  admin: string;           // e.g., "GP", "Chair", "Director", "President"
  guest: string;           // e.g., "LP", "Visitor", "Guest", "Donor"
  [key: string]: string;   // Extensible
}
```
