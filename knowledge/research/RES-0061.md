# Cue App: Multi-Organization Architecture Design

## Executive Summary

This document defines the complete multi-organization architecture for the Cue App, enabling support across nine distinct organization types. The design establishes a composable, profile-driven system where organizations configure their workspace through industry profiles, feature flags, and configurable fields — without requiring separate codebases or complex multi-tenant infrastructure at this stage.

---

### 1.2 Workspace Model

A Workspace is the primary operational unit within an Organization. Organizations may have multiple Workspaces (e.g., a VC firm with "Fund I" and "Fund II"; a conference org with "SaaStr 2024" and "SaaStr 2025").

```typescript
// src/models/workspace.ts

export enum WorkspaceType {
  // VC / PE
  FUND = 'fund',
  PORTFOLIO = 'portfolio',
  DEAL_PIPELINE = 'deal_pipeline',
  
  // Events
  EVENT = 'event',
  PROGRAM = 'program',
  
  // Community / Alumni
  COHORT = 'cohort',
  CHAPTER = 'chapter',
  COMMITTEE = 'committee',
  
  // General
  GENERAL = 'general',
}

export interface WorkspaceQuota {
  maxMembers: number | null;
  maxGuests: number | null;
  maxStorageGb: number | null;
  maxEvents: number | null;
}

export interface Workspace {
  id: string;
  organizationId: string;        // FK → Organization
  slug: string;                  // unique within org
  displayName: string;
  description: string | null;
  type: WorkspaceType;
  
  // Inherit from org profile, override per workspace
  featureOverrides: Partial<FeatureFlags>;
  fieldOverrides: Partial<FieldConfiguration>;
  
  isDefault: boolean;            // one default per org
  isArchived: boolean;
  
  quota: WorkspaceQuota;
  
  parentWorkspaceId: string | null;   // for nested workspaces (future)
  
  createdBy: string;             // FK → User
  createdAt: Date;
  updatedAt: Date;
}
```

## 2. Industry Profile System

Industry Profiles are the primary mechanism for configuring the Cue App's behavior per organization type. A profile is a named, versioned bundle of feature flags, field configurations, terminology overrides, and UI hints.

```typescript
// src/models/industry-profile.ts

export interface TerminologyMap {
  // Maps generic Cue terms to industry-specific equivalents
  // key = Cue canonical term, value = display label
  member: string;          // e.g., "LP", "Attendee", "Alumni", "Constituent"
  organization: string;    // e.g., "Fund", "Portfolio Co", "Chapter"
  workspace: string;       // e.g., "Fund", "Event", "Cohort"
  event: string;           // e.g., "Meeting", "Summit", "Reunion"
  connection: string;      // e.g., "Deal", "Registration", "Membership"
  profile: string;         // e.g., "Founder", "Delegate", "Member"
  note: string;            // e.g., "Deal Note", "Session Note", "Touch"
  tag: string;             // e.g., "Thesis", "Track", "Interest Area"
  stage: string;           // e.g., "Funnel Stage", "Check-In Status", "Pipeline"
}

export interface IndustryProfile {
  id: string;
  version: string;               // semver, e.g. "1.2.0"
  organizationType: OrganizationType;
  displayName: string;           // e.g., "Venture Capital"
  description: string;
  
  defaultFeatureFlags: FeatureFlags;
  defaultFieldConfiguration: FieldConfiguration;
  terminology: TerminologyMap;
  
  // Suggested workspace types for onboarding
  suggestedWorkspaceTypes: WorkspaceType[];
  
  // UI hints for onboarding wizard
  onboardingFlow: string;        // e.g., "vc_onboarding_v1"
  
  isActive: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```
