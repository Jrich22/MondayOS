  session, an expired-presence session, or a stale one. Tested in all three states.'
- 'Every MCP write requires a live session AND `operatorPresent()`. On expiry the write fails
  with `operator_absent` AND the session auto-pauses. Tested at the 15-minute boundary.'
- 'The "I''m still here" control refreshes presence, and designated ordinary UI interactions
  refresh it too. A test asserts an idle session past the window cannot be written to until
  presence is refreshed.'
- 'One candidate per call. No batch or bulk tool exists in the tool list, asserted by a test —
  this is the mechanical control against bulk export.'
- '`add_candidate` refuses when `findDuplicatesFor` returns matches, returning
  `{ ok: false, code: "possible_duplicates", candidates }`. It NEVER auto-merges. Proceeding
  requires either `reuse_candidate` or an explicit `confirmedDistinctFrom`. Both paths tested.'
- '`add_candidate` and `reuse_candidate` route through `captureCandidate` and `commitCapture`,
  so a half-applied capture remains impossible across the MCP boundary. `record_close_call`
  and `record_skip` route through `recordSkip` with `closeCall` true and false respectively.'
- 'Every record written via MCP carries `sessionId`, `reqId`, `briefVersion`, `decidedBy`,
  and `proposedBy: "claude"`, so who proposed and who decided stay separately attributable.'
- '`ClaudeChromeProvider` declares `agentOperatesBrowser: true` and its own supervision policy
  text, which states that Claude operates the browser, that the operator is present throughout,
  that every decision is the operator''s, that the session stops on any platform warning, and
  that the operator accepts the terms-of-service risk (ADR-015). A test asserts the
  ToS-risk line is present and that the ManualProvider wording is NOT reused.'
- '`ClaudeChromeProvider` contains no browser control, no navigation, no URLs, no CSS or DOM
  selectors, no retry or pacing logic, and no credentials. A test greps the provider module
  and fails on any of these — the boundary is enforced, not promised.'
- 'The live session console shows status, provider, brief version, live counters, the presence
  indicator with remaining time, the copyable session pointer, and pause/halt/complete controls.
  Counters update over SSE as Claude writes, without a refresh.'
- 'A halt from `halt_session` is visibly distinct from a pause in the console and requires a
  fresh acknowledgement to resume.'
- 'Starting an agent-operated session still requires a named operator and a ticked
  acknowledgement of the ClaudeChromeProvider policy; `startSession` refuses all three ways.'
- '`ManualProvider` remains fully functional and is still the default. A test asserts the
  manual path works with the MCP server absent.'
- '`PROHIBITED_CAPABILITIES` unchanged; `supportsCapability()` still returns false for every
  entry. No unattended, scheduled, or background sourcing; no rate-limit, CAPTCHA, or
  automation-evasion behaviour anywhere in the diff.'
- 'Setup is documented in `projects/sourcingbot/README.md`: registering the MCP server with
  Claude Code, `claude --chrome`, and the one-time Chrome native-host install.'
- 'Full validation green: sourcingBOT `vitest`, TypeScript strict, production build, MondayOS
  `pytest`, and Cue App tests with zero Cue changes.'
