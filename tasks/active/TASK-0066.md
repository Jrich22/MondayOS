acceptance_criteria:
- The Brain is a layer inside growth/, scoped to ONE workspace. A test asserts a Brain built for project A cannot read project
  B's content, campaigns, memory, or events.
- 'The Brain distinguishes four record kinds and never conflates them: Observation (computed fact with its source), Hypothesis
  (a candidate explanation, explicitly unconfirmed), Recommendation (a proposed action), and ConfirmedLearning (a hypothesis
  an experiment upheld).'
- A Hypothesis rendered anywhere carries an explicit unconfirmed marker. A test asserts no output path presents a hypothesis
  with the same shape as an observation or a confirmed learning.
- 'Recommendation carries: id, project, type, title, explanation, evidence, confidence, expected_impact, suggested_action,
  success_metric, falsifier, created_at, status. A recommendation missing evidence or falsifier is refused at construction,
  tested.'
- 'Recommendation status is a state machine: proposed, accepted, rejected, completed, invalidated. Illegal transitions raise.'
- 'Brain analysis in this increment is DETERMINISTIC: recommendations derive from stored content, campaigns, and metrics
  by explicit rules, not from a model call. A test asserts the same workspace state yields byte-identical recommendations
  across runs.'
- No causal claim is emitted without supporting evidence. A test feeds a workspace with a performance difference below the
  configured minimum sample and asserts the Brain emits a hypothesis, never a causal recommendation.
- MarketingMemory is project-scoped and stores statement, evidence, source campaigns/content, sample_size, confidence, date_range,
  metric_affected, and status (tentative | validated | invalidated). A test asserts memory never crosses projects.
- The Brain may cite validated memory freely; tentative memory is always labelled tentative in output. Tested.
- 'Opportunity types: content gap, channel, SEO, campaign, reuse, conversion, audience, partnership. Each carries evidence,
  expected upside, confidence, proposed action/experiment, and success metric.'
- An opportunity with no supporting data reports its upside as unknown rather than a fabricated number. A test asserts no
  quantified estimate is emitted without backing events.
- Experiment carries project, campaign, hypothesis, variation_a, variation_b, metric, minimum_sample, start/end, status,
  result, conclusion, with status proposed, approved, running, completed, inconclusive, cancelled.
- An experiment whose sample is below minimum_sample resolves to inconclusive, never to a winner. Tested.
- Running an experiment that changes published content requires explicit human approval; a test asserts no code path starts
  such an experiment without it.
- ADR-014 is updated in docs/DECISIONS.md from Proposed to Accepted, stating that the measurement layer from Increment 5
  is what made it implementable.
